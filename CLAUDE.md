# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

**Mochi** — a mobile-first, offline-first personal expense tracker PWA. All data lives in the
browser (IndexedDB via Dexie); there is no backend. UI copy is **Vietnamese**, currency is **VND**.

## Commands

```bash
npm install        # .npmrc sets legacy-peer-deps=true
npm run dev        # Vite dev server → http://localhost:5173 (SW enabled in dev)
npm run build      # tsc -b && vite build → dist/
npm run lint       # ESLint (flat config)
npm run preview    # serve the production build
```

There is no test suite. Before finishing a change, run `npm run lint` and `npm run build`
(the build is the type check).

## Stack

React 19 · TypeScript (strict) · Vite 8 · Tailwind CSS 4 (`@theme` tokens in `src/index.css`,
no tailwind config file) · shadcn/ui on Radix (`src/components/ui`) · vaul drawers · Zustand ·
Dexie + `dexie-react-hooks` · Recharts · framer-motion · date-fns · sonner · lucide-react ·
vite-plugin-pwa (`injectManifest`) · Vercel Speed Insights.

Path alias: `@/` → `src/`.

## Architecture

```
src/
  App.tsx          # init (seed → load categories → fixed-expense check), screen stack, tabs
  main.tsx
  sw.ts            # custom service worker: precache + daily recurring reminder notifications
  components/      # shared UI; components/ui = shadcn primitives
  features/<name>/ # screens & feature components (home, quick-add, calendar, dashboard,
                   #   recurring, fixed-expenses, settings, transactions)
  hooks/           # data hooks (mostly useLiveQuery over Dexie) and UI hooks
  stores/          # Zustand stores (app UI state, CRUD wrappers over Dexie)
  lib/             # db, utils, backup/export, notifications, personalization, launch params
  types/index.ts   # domain types + seed categories + palettes
```

- **Navigation** is a hand-rolled screen stack in `App.tsx` (`Screen` union + `push`/`pop`
  synced with `window.history`). No router. Bottom tabs: `home | budget | calendar | overview`.
  Last tab is persisted in `localStorage['active-tab']`.
- **Reactive reads**: prefer `useLiveQuery` in hooks; stores are used for writes and shared UI state
  (e.g. `useAppStore().openQuickAdd(...)`).
- **Heavy screens** (Calendar, Dashboard, Budget) are `lazy()`-loaded with `Suspense`.
- **Launch params** (`lib/launchParams.ts`): `/?add=35000&cat=cafe`, `/?tab=calendar` — used by
  manifest shortcuts in `vite.config.ts`. Category matching strips Vietnamese diacritics.

## Data rules (important)

- DB name `ChiTieuDB`, schema in `src/lib/db.ts`. **Never edit an existing `db.version(n)`** —
  add a new version (with `.upgrade()` if data must change). Users' data is on-device only, so a
  broken migration cannot be fixed server-side.
- `Transaction.date` is a `'YYYY-MM-DD'` string — never a `Date` or timestamp. Use helpers in
  `lib/utils.ts` (`getTodayString`, `formatDateToString`, ...). Month keys are `'YYYY-MM'`.
- Amounts are raw integer VND numbers; format only for display (`formatVND`, `formatShort`).
- Deletion is **soft** (`deletedAt`) with an undo window, then hard delete. Every spending query
  must exclude `deletedAt` rows.
- `isNote: true` transactions are kept in history but **excluded from all totals** (budget,
  calendar heatmap, dashboard). Use `sumSpent()` or filter `!tx.isNote`.
- If you add a table or field, update backup/restore (`lib/backup.ts`, `lib/data-export.ts`) too.
- Small preferences live in `localStorage` (`active-tab`, `personalization`,
  `install-banner-dismissed`, notification settings).

## UI conventions

- Mobile-first, max width ~480px, dark navy theme. Use theme tokens (`bg-card`, `text-text-muted`,
  `text-accent-dark`, `bg-surface2`, ...) from `src/index.css` — avoid hard-coded colors.
  Accent color is user-customizable at runtime (`applyAccentColor`), so use `--color-accent*`.
- Design reference: `design-system/moneyapp/MASTER.md`.
- Tap targets ≥ 44px (global `button { min-height: 44px }`; see `closeButtonClass` in `lib/utils.ts`).
- Call `triggerHaptic()` (`lib/haptic.ts`) on meaningful taps, consistent with existing components.
- iOS Safari quirks matter: keyboard handling goes through `useIOSKeyboard` / `useKeyboardInset`.
  Test sheets/inputs with the on-screen keyboard in mind.
- All user-facing strings are Vietnamese.

## Code style

- Match surrounding code: functional components, named exports, `type` imports
  (`verbatimModuleSyntax`), short `// ──` section comments, JSDoc on non-obvious helpers.
- Keep react-refresh happy: component files should only export components (shared constants go
  in `lib/`).
- Commit messages: conventional commits (`feat:`, `fix:`, `refactor:`), English.

## Gotchas

- `dev-dist/` is generated by the PWA plugin in dev mode but is currently tracked in git — avoid
  committing incidental changes to it.
- Service worker updates surface as a "Có bản cập nhật mới" toast (`useRegisterSW` in `App.tsx`).
- Deploy target is static hosting (Vercel): build `npm run build`, output `dist`.
